# Terminal UI / Python protocol

The UI starts `python -u -m shell_e.bridge`. Each message is one JSON object per
line. Stdout is reserved for events; startup diagnostics go to stderr. No socket
or application web server is involved. On stdin EOF, shutdown, SIGINT, or SIGTERM,
Python cancels the current task and cleans up running command processes.

UI requests:

| Type | Fields | Purpose |
| --- | --- | --- |
| `prompt` | `text` | Start one task |
| `approval` | `id`, `approved` | Respond to the matching pending command |
| `cancel` | — | Cancel inference, approval, or execution |
| `cd` | `path` | Change session directory while idle |
| `reset` | — | Clear model history while idle |
| `shutdown` | — | Clean up and exit |

Python events:

| Type | Fields | Purpose |
| --- | --- | --- |
| `ready` | `model`, `cwd` | Startup or successful idle control request |
| `status` | `text` | Task progress |
| `text` | `text` | Model text fragment |
| `tool` | `name`, `arguments` | Tool invocation |
| `approval` | `id`, `command`, `explanation`, `cwd`, `timeout_ms` | Exact command pending a decision |
| `output` | `stream`, `text` | Incremental stdout or stderr |
| `result` | `name`, `result` | Structured tool result |
| `error` | `text` | Request or task error |
| `done` | `cwd` | Task finished, failed, or cancelled |

Only one task and one approval may be active. Approval IDs are generated by
Python; stale answers are ignored. Approval is never inferred from model output.
A rejection stops the task. The core validates tool arguments before requesting
approval. The UI visibly escapes terminal control characters before rendering
external text.
